                    1. INTRODUCTION & SYSTEM OVERVIEW
================================================================================

WHAT IS LOGITRACK?
------------------
LogiTrack is a logistics and inventory management platform designed for 
e-commerce sellers. It helps track:

- Products and inventory batches (with expiry tracking)
- Orders from multiple sales channels (Shopee, manual entry)
- Shipments via TracxLogis carrier integration
- Reorder alerts and stock level monitoring

WHY DOES IT EXIST?
------------------
E-commerce sellers often struggle to manage:
1. Inventory across multiple batches with different expiry dates
2. Orders coming from different sales channels
3. Shipment tracking from various carriers
4. Low stock alerts and reorder timing

LogiTrack consolidates all these concerns into one dashboard.

HOW IT WORKS (HIGH LEVEL):
--------------------------
1. Sellers connect their Shopee shop via OAuth
2. Orders sync automatically from Shopee (or can be created manually)
3. Inventory is managed in "batches" (each batch can have its own expiry date)
4. When orders are fulfilled, shipments are created and tracked via TracxLogis
5. Dashboard shows alerts for low stock, expiring items, and shipment status

KEY FOLDER EXPLANATIONS:
------------------------

/app/api/ - Backend Logic
    All REST API endpoints live here. Each folder is a route.
    Example: /app/api/orders/route.ts handles GET/POST to /api/orders

/app/dashboard/ - Protected Pages
    All pages under this folder require authentication.
    The layout.tsx checks for session and redirects if not logged in.

/lib/ - Business Logic & Utilities
    This is where the "meat" of the application lives:
    - API clients (Shopee, TracxLogis)
    - Authentication configuration
    - Type definitions
    - Database client

/prisma/ - Database Schema
    Contains the Prisma schema that defines all database tables.
    Run "yarn prisma generate" after changing this file.

/components/ui/ - UI Component Library
    Pre-built components from shadcn/ui. These are copied into the
    project (not installed as npm packages) so they can be customized.

---------------
All API routes (except /api/auth/* and /api/signup) require authentication.

REQUEST LIFECYCLE:
------------------
1. Client sends request with session cookie
2. API route calls getServerSession(authOptions)
3. If no session, return 401 Unauthorized
4. If session valid, proceed with business logic
5. Query/mutate database via Prisma
6. Return JSON response

================================================================================
                    6. STATE MANAGEMENT & DATA FLOW
================================================================================

ORDER STATUS LIFECYCLE:
-----------------------
Orders follow a strict state machine. Invalid transitions are rejected.

    PENDING
       │
       ├──────────→ CANCELLED (terminal)
       ↓
   CONFIRMED
       │
       ├──────────→ CANCELLED
       ↓
   PROCESSING
       │
       ├──────────→ CANCELLED
       ↓
    SHIPPED
       │
       ├──────────→ CANCELLED
       ↓
   DELIVERED
       │
       ↓
    REFUNDED (terminal)

Valid Transitions:
- PENDING → CONFIRMED, CANCELLED
- CONFIRMED → PROCESSING, CANCELLED
- PROCESSING → SHIPPED, CANCELLED
- SHIPPED → DELIVERED, CANCELLED
- DELIVERED → REFUNDED
- CANCELLED → (none - terminal state)
- REFUNDED → (none - terminal state)

SPECIAL BEHAVIOR:
- On CANCELLED: Inventory is automatically restored
- On DELETE: Only PENDING/CANCELLED orders can be deleted; inventory restored

SHIPMENT STATUS LIFECYCLE:
--------------------------

    PENDING
       │
       ↓
   PICKED_UP
       │
       ↓
   IN_TRANSIT
       │
       ↓
 OUT_FOR_DELIVERY
       │
       ├──→ FAILED (can retry)
       ↓
   DELIVERED
       │
       ↓
    RETURNED (if customer rejects/returns)

TRACKING SYNC FLOW:
-------------------
1. User creates shipment with tracking number
2. User clicks "Sync" or "Sync All"
3. System calls TracxLogis API with tracking number
4. TracxLogis returns tracking events
5. System maps TracxLogis status to internal status
6. Shipment and Order statuses are updated
7. Tracking history is stored as JSON

INVENTORY FLOW:
---------------
- Stock is tracked at BATCH level, not product level
- Product's "total stock" = sum of all batch quantities
- When order is created with batch links, stock is deducted
- When order is cancelled/deleted, stock is restored
- Expiry is tracked per batch

DATA FLOW EXAMPLE - ORDER CREATION:
-----------------------------------
1. User submits order form (UI)
2. POST /api/orders with items array
3. Server validates:
   - Channel is valid (shopee/manual)
   - Items have required fields
   - Quantities > 0
4. Order created in database with auto-generated order number
5. If inventoryBatchId provided:
   - Batch quantity decremented by item quantity
6. Response returned with created order
7. UI updates order list

================================================================================
                    8. AUTHENTICATION & AUTHORIZATION
================================================================================

AUTHENTICATION MECHANISM:
-------------------------
LogiTrack uses NextAuth.js with the Credentials provider.

How it works:
1. User submits email/password on /login page
2. NextAuth calls authorize() function in lib/auth.ts
3. authorize() looks up user by email in database
4. Password compared using bcrypt.compare()
5. If valid, JWT token created and stored in HTTP-only cookie
6. Session available via useSession() hook or getServerSession()

KEY FILES:
- lib/auth.ts - NextAuth configuration
- app/api/auth/[...nextauth]/route.ts - Auth endpoints
- app/api/signup/route.ts - User registration
- components/providers.tsx - SessionProvider wrapper

SESSION STRATEGY:
-----------------
Using JWT strategy (stateless):
- Token stored in HTTP-only cookie
- Contains user id, email, name
- No database lookup needed for session validation
- Token refreshed on each request

PROTECTING PAGES:
-----------------
Dashboard pages are protected in app/dashboard/layout.tsx:

```typescript
const session = await getServerSession(authOptions);
if (!session) {
  redirect('/login');
}
```

PROTECTING API ROUTES:
----------------------
All API routes check session:

```typescript
const session = await getServerSession(authOptions);
if (!session) {
  return NextResponse.json(
    { success: false, error: 'Unauthorized' },
    { status: 401 }
  );
}
```

ROLES & PERMISSIONS:
--------------------
Currently, LogiTrack has a SINGLE ROLE: authenticated user.
All authenticated users have full access to all features.

There is NO role-based access control (RBAC) implemented.
All users can:
- View and manage all products
- View and manage all orders
- View and manage all shipments
- Connect Shopee shops
- Configure TracxLogis

Future Enhancement: Add role field to User model (admin, manager, viewer)

                    11. DEBUGGING, LOGGING & ERROR HANDLING
================================================================================

LOGGING STRATEGY:
-----------------
LogiTrack uses console.log/console.error for logging.
Logs appear in:
- Terminal (when running yarn dev)
- Server logs (in production)

Common log patterns:
```typescript
console.log('Processing order:', orderId);
console.error('Error creating order:', error);
console.log('Shopee sync completed:', { imported: 5, skipped: 2 });
```

DEBUGGING TIPS:
---------------

1. API Not Working?
   - Check browser Network tab for request/response
   - Look for 401 (not logged in) or 400 (validation error)
   - Check terminal for server-side errors

2. Database Issues?
   - Run: yarn prisma studio
   - This opens a GUI to browse database
   - Check if records exist as expected

3. Shopee Integration Issues?
   - Check if using sandbox vs production URL
   - Verify Partner ID is valid integer
   - Check token expiration in shopee_configs table
   - Look for "error_sign" or "error_auth" in responses

4. TypeScript Errors?
   - Run: yarn prisma generate (regenerates types)
   - Check import paths are correct

COMMON ERRORS & FIXES:
----------------------

Error: "@prisma/client did not initialize yet"
Fix: Run `yarn prisma generate`

Error: "Unauthorized" (401)
Fix: Make sure you're logged in. Check session cookie exists.

Error: "Cannot transition from X to Y"
Fix: This is a valid business rule. Check ORDER_STATUS_TRANSITIONS.

Error: "A configuration for this shop already exists"
Fix: Shop ID is unique. Delete existing config first.

Error: "Invalid partner_id" from Shopee
Fix: Partner ID must be sent as integer, not string.

Error: "error_sign" from Shopee
Fix: Signature calculation is wrong. Check:
  - Partner ID is integer in base string
  - Timestamp is current Unix timestamp
  - Using correct partner key

ERROR HANDLING PATTERN:
-----------------------
API routes follow this pattern:

```typescript
try {
  // Business logic
  return NextResponse.json({ success: true, data: result });
} catch (error) {
  console.error('Error description:', error);
  return NextResponse.json(
    { success: false, error: 'User-friendly message' },
    { status: 500 }
  );
}
```

================================================================================
                    12. CODE CONVENTIONS & PATTERNS
================================================================================

ARCHITECTURAL PATTERNS:
-----------------------

1. Feature-based folder structure
   - API routes grouped by domain (orders, products, etc.)
   - Each domain has its own folder under /app/api

2. Singleton database client
   - Prisma client instantiated once in lib/db.ts
   - Prevents connection pool exhaustion in development

3. Type-safe API responses
   - All responses follow ApiResponse<T> shape
   - TypeScript types defined in lib/types.ts

4. Server-side authentication
   - getServerSession() called in every API route
   - Dashboard layout checks session on server

NAMING CONVENTIONS:
-------------------

Files:
- React components: PascalCase.tsx (Sidebar.tsx)
- Pages: lowercase/page.tsx (dashboard/orders/page.tsx)
- API routes: lowercase/route.ts (api/orders/route.ts)
- Utilities: kebab-case.ts (shopee-client.ts)

Variables:
- camelCase for variables and functions
- PascalCase for types and interfaces
- UPPER_SNAKE_CASE for constants

Database:
- snake_case for table names (via @@map)
- camelCase for Prisma model fields

CODE PATTERNS:
--------------

API Route Structure:
```typescript
import { NextRequest, NextResponse } from 'next/server';
import { getServerSession } from 'next-auth';
import { authOptions } from '@/lib/auth';
import { prisma } from '@/lib/db';

export async function GET(request: NextRequest) {
  const session = await getServerSession(authOptions);
  if (!session) {
    return NextResponse.json({ success: false, error: 'Unauthorized' }, { status: 401 });
  }

  try {
    const data = await prisma.model.findMany();
    return NextResponse.json({ success: true, data });
  } catch (error) {
    console.error('Error:', error);
    return NextResponse.json({ success: false, error: 'Failed' }, { status: 500 });
  }
}
```

React Component Pattern:
```typescript
'use client';

import { useState, useEffect } from 'react';
import { toast } from 'sonner';

export default function MyPage() {
  const [data, setData] = useState([]);
  const [loading, setLoading] = useState(true);

  const fetchData = async () => {
    try {
      const res = await fetch('/api/endpoint');
      const json = await res.json();
      if (json.success) {
        setData(json.data);
      } else {
        toast.error(json.error);
      }
    } catch (error) {
      toast.error('Failed to fetch data');
    } finally {
      setLoading(false);
    }
  };

  useEffect(() => { fetchData(); }, []);

  if (loading) return <div>Loading...</div>;
  return <div>{/* render data */}</div>;
}
```

DO NOT DO THIS:
---------------
❌ Don't import prisma directly in components (only in API routes)
❌ Don't store sensitive data (tokens, keys) in client-side state
❌ Don't skip session checks in API routes
❌ Don't use string partner IDs in Shopee API calls
❌ Don't delete orders without checking status first
❌ Don't modify inventory without proper order status handling

LEGACY/SENSITIVE AREAS:
-----------------------
⚠️ lib/shopee-client.ts - Signature generation is complex and fragile
⚠️ Order status transitions - Business rules enforced here
⚠️ Inventory deduction - Must match order item flow
